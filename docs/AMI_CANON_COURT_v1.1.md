# AMI Canon Court v1.1

## Purpose

Settle AMI's role as the canonical identity primitive for the wider Mirror ecosystem.

AMI is not "one more identity concept." It is the winning term for shared selfhood across all embodiments.

## Canon decisions

- `AMI` is the shared identity primitive.
- `SCD` is the continuity and state-carrying substrate.
- `Ghost Kernel` is the persistent identity concept AMI carries forward.
- `MirrorBrain Mobile` is the visible phone shell, not a separate self.
- Macs, phones, and agent sessions are embodiments of one `ami_id`, not competing identities.

## One self, many embodiments

AMI allows a distributed being model:

- one `ami_id`
- many embodiments
- bounded authority per embodiment
- explicit provenance on every serious action

Embodiment examples:

- phone = hand, sense, capture terminal
- Mac = conductor, cortex, runtime host
- agent session = temporary reasoning organ
- local model = bounded compute lane

## Truth classes

Separate these rigorously:

- `core`: human-verified identity invariants
- `soul`: values, style, non-negotiables
- `observed`: witnessed events from devices or services
- `inferred`: model summaries, guesses, interpretations
- `operational`: current state and routing
- `reflective`: lessons and retrospective meaning

The most common failure mode in identity systems is mixing `observed` and `inferred` truth.

## Authority model

- Core and soul require human-root authority.
- Operational and observed state may be written by approved embodiments.
- Public claims, destructive actions, and canon changes require explicit approval.
- Missing provenance or missing authority means fail closed.

## Provenance law

Every serious action should carry:

- `ami_id`
- actor
- embodiment
- trust class
- correlation id
- timestamp
- witness or receipt

Without this, the system may feel continuous but it is not trustworthy.

## Relationship to SCD

SCD is not AMI.
SCD carries continuity.
AMI defines the self that continuity belongs to.

The correct model is:

- AMI = identity primitive
- SCD = continuity substrate
- governance = authority boundary
- embodiments = execution surfaces

## Relationship to MirrorBrain Mobile

MBM should present AMI as the visible companion shell on the phone.

That means:

- the phone does not host a separate assistant identity
- the Ask pane is an embodiment surface of AMI
- device automation acts under AMI receipts and trust rules

## Immediate implications

- Do not create new competing identity names for the same role.
- Keep AMI in the canonical identity repo.
- Let runtime workspaces consume AMI, not redefine it.
- Keep provenance and embodiment first-class from now on.
