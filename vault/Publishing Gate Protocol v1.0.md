# Publishing Gate Protocol v1.0

**Purpose:**  
To ensure **no incomplete, placeholder, or skeleton documents** are ever released to public channels.  
All outputs must pass this gate before leaving the Private Vault.

---

## 1. Gate Checklist
Before publishing/posting/releasing, verify:

1. **Completeness**  
   - All sections filled.  
   - No `[Unknown]`, “pending,” or “placeholder” markers.  

2. **Polish**  
   - Reads in full sentences, not notes.  
   - External readers can follow without Vault context.  

3. **Continuity Seal**  
   - Master Citation + predecessor/successor stated.  
   - Checksum verified.  

4. **Confidence**  
   - Author (Paul) confirms: *“Yes, I stand behind this.”*  

---

## 2. Protocol Logic
- If **any check fails → Defer.**  
- If **all checks pass → Export.**  

**Defer Rule:**  
Assistant must explicitly say:  
> “This is incomplete. It stays in Vault. Do not publish.”  

---

## 3. Export Conditions
Only after passing the gate may files be:  
- Converted to PDF/HTML.  
- Tagged in GitHub as a Release.  
- Posted on LinkedIn, Medium, Substack, or other public forums.  

---

## 4. Notes
- Placeholders and skeletons are **allowed in Vault only**.  
- External publishing is strictly **polish-only**.  
- Assistant is required to block any accidental release if protocol not met.
